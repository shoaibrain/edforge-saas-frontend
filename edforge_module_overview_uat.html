D-03
CRITICAL
All recent payments show timestamp "Yesterday · 7:00 PM" regardless of actual time
In the Finance recent payments feed, every payment shows the same relative timestamp. RCP-0013 was created at 13:54 today, RCP-0010 at 04:56 today, RCP-0005 on March 17. They should show different times. The 7:00 PM is almost certainly a UTC-to-local conversion error that collapses all timestamps to a default value.
Fix required
Fix `formatRelativeDate()` in `@edforge/types`. The function must parse ISO timestamps correctly using the browser's locale timezone — use `new Date(isoString)` and then `Intl.RelativeTimeFormat` or `date-fns/formatRelative`. Never hardcode a time. Today's payments should show "Today · 1:54 PM", "Today · 4:56 AM" etc.
Finance
D-04
CRITICAL
Outstanding KPI tag says "32 pending" — semantically incorrect
"Pending" in finance means an invoice not yet issued. "Outstanding" means money owed. The 32 in this context are overdue invoices, not pending ones. Mixing these terms will confuse school admins and accountants who understand financial terminology.
Fix required
Change the Outstanding KPI tile tag from "32 pending" to "32 awaiting payment" or simply derive from `invoicesByStatus.issued + invoicesByStatus.partially_paid + invoicesByStatus.overdue`. The overdue-specific count should appear on the Overdue tile only.

The "Academics overview" H1 + subtitle + year chip pattern takes up approximately 80px of vertical space before any meaningful content. On a 900px viewport, this pushes KPI tiles below the fold. More critically, the header copy is generic — "Academics overview" tells a school admin nothing they don't already know from the sidebar nav they just clicked. E-02
ENHANCE
Finance: replace static aging report buckets with a visual spectrum chart
The five aging buckets as cards is functional but not expressive. A heat-map style horizontal spectrum where bucket width is proportional to amount and color intensity increases with age (Current = faint green → 1-30 days = amber → 31-60 = red → 61-90 = deep red → 90+ = near-black red) would communicate aging urgency at a glance without reading numbers. This is the kind of creative data visualization that sets enterprise products apart.
Implementation
Build an `AgingSpectrumChart` component. Full-width bar divided into segments. Each segment width = `bucket.amount / totalOverdue * 100%`. Each segment has a label above (bucket name) and amount below. Color: Current `#1D9E75`, 1-30 `#EF9F27`, 31-60 `#E24B4A`, 61-90 `#A32D2D`, 90+ `#501313`. When a bucket has 0 amount, render a thin 4px divider placeholder so the spectrum stays visually complete. For the current data (all 32 invoices in 1-30 days) this would show one full amber block — a clear, immediate visual.

E-03
ENHANCE
Academics: replace static enrollment bar chart with an interactive bubble/dot grid
The enrollment by grade level chart uses horizontal bars — the same visual pattern as the collection performance bars in Finance. Both pages start feeling like the same chart repeated. For enrollment distribution, a dot matrix or bubble grid would be more humanized: each student is represented as a colored dot grouped by grade. 22 students = 22 dots, organized in rows by grade. This makes enrollment tangible — you see individual students rather than a bar representing an abstraction.
Implementation
Build a `StudentDotMatrix` component. SVG grid where each student is a 8px circle with 3px gap. Group by grade level in rows, label each row with the grade name on the left. Circle color encodes grade tier: early elementary (PK-2) teal, middle (3-6) blue, high school (7-12) purple. Hovering a row highlights all dots in that grade and shows a tooltip: "Grade 10 · 4 students · 18.2% of enrollment." For 22 students this fits comfortably in a 200px card height.

ENHANCE
Finance: quick-select time filters instead of raw date inputs
The current date range filter requires manual date entry (mm/dd/yyyy inputs) which is slow and error-prone for daily use. School accountants check finance daily — they never need arbitrary date ranges. They need "Today", "This week", "This month", "This academic year".

Keep manual date range as a "Custom" option that expands the picker inline when selected.

When a section has no data (zero overdue, no at-risk students, etc.), the current UI shows bars at zero width, counts at 0, amounts at NPR 0. This looks broken.
