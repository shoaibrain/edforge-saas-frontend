Move the theme switcher into the avatar menu

Today EdForge exposes two user preferences in two different places, in two different visual styles: the theme pill (Light | Dark) floats loose in the top bar as a white-chip toggle, while the language toggle (EN | NP) already lives inside the avatar menu as a green-pill toggle. This prototype pulls the theme control into the menu and unifies both into a single Preferences group — label-left, control-right, one consistent pill style. The top bar is left with just the avatar. Flip Theme and Lang in the header (or click the controls inside the proposed menu) to drive the live mockups.

Implementation handoff

Everything the implementing agent needs. One file does the work; two i18n files add the labels.

Single file to edit

  • apps/shell/src/components/layout/Header.tsx — owns both the top-bar ThemePill and the UserMenu dropdown.

1 · Remove the theme pill from the top bar

  • In Header(), the right zone renders <ThemePill /> <UserMenu />. Drop <ThemePill /> so only the avatar remains.
  • Delete the now-unused ThemePill function (≈ lines 104–136). grep confirms it is referenced only here — no other importers.
- <div className="flex items-center gap-0.5 flex-shrink-0 pr-4">
-   <ThemePill />
-   <UserMenu />
- </div>
+ <div className="flex items-center flex-shrink-0 pr-4">
+   <UserMenu />
+ </div>

2 · Add an AppearanceToggle (mirror of LanguageToggle)

  • Clone LanguageToggle's markup exactly so the two controls are visually identical: same seg container, same layoutId-style sliding pill, same active --action-primary-bg fill.
  • Wire it to the theme store already imported in this file: const { resolvedTheme, setTheme } = useThemeStore(); segments call setTheme('light') / setTheme('dark'); active = resolvedTheme === code.
  • Give the motion pill a distinct layoutId (e.g. "appearance-toggle-pill") so it animates independently of the language pill.
  • role="radiogroup" + role="radio" / aria-checked, matching LanguageToggle's a11y.

3 · Replace the lone language block with a Preferences group

  • In UserMenu, the current language block is a single right-aligned <LanguageToggle />. Replace it with a labelled two-row group: a tNav('preferences') heading, then an Appearance row and a Language row — each flex items-center justify-between with an icon + label on the left and the toggle on the right.
  • Suggested icons (lucide, already a dep): Sun/Moon for Appearance, Languages (or Globe) for Language.

4 · i18n labels

  • Add to packages/i18n/src/locales/en/nav.json and …/ne/nav.json: preferences, appearance, language (and optionally light/dark if you don't keep them literal — current ThemePill hardcodes them in English).
  • NP fallbacks used in this mockup: प्राथमिकताहरू (Preferences), रूप (Appearance), भाषा (Language). Confirm with the team's translator.

Verify (per CLAUDE.md — route → component, then render-path smoke)

  • pnpm dev:shell → open any module, click the avatar. Confirm: top bar shows avatar only; menu shows Appearance + Language together; toggling Appearance flips the whole shell theme; language toggle still switches EN/NP.
  • pnpm --filter @edforge/shell typecheck and the shell unit tests. No API-Gateway/route changes — this is shell-only UI.
